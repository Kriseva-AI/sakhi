# Contributing

Start with README.md and docs/SAFETY.md. Run make setup, make dev and make verify. Use synthetic examples only. Never submit private stories, identities, intimate imagery, credentials or personal case documents through issues, tests or screenshots.

Resource corrections need an authoritative public source, date, scope and proposed diff. Discovery leads never become public simply by import. Critical contacts need human verification and a second review. Translations require native language and safeguarding expert signoff; see docs/TRANSLATION_REVIEW.md. Never change review_pending to reviewed_for_scope without evidence.

Good first issues: document a reproducible setup on another OS; add independent nonsensitive retrieval fixtures; improve keyboard behavior; review a public source's scope; arrange qualified translation review. Implementation issues are prepared in docs/ISSUE_BACKLOG.md and not yet published remotely.

Pull requests must describe behavior, source provenance, safety impact, accessibility and actual test results. No auto-send integrations, tracking scripts, account requirement or personal persistence may enter T0. P1/P2 wait for the P0 gates. Maintainer approval is required before deployment.
