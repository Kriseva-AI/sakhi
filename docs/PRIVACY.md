# Privacy and data flow

Sakhi has no account, people database, evidence upload, cloud model or analytics. Optional audio/video file previews and voice-note recording stay in temporary browser memory; they are not uploaded, transcribed or interpreted. Support choices and optional words exist in browser app memory. POST /api/navigate processes them on the Sakhi server, without saving or logging the text. The SQLite index contains public category vocabulary only. Synthetic mode disables live lookups, geolocation, calls, external opens and downloads.

Only an explicitly chosen sakhi.locale preference is stored in localStorage. Initial loading does not create it. Removing it does not restore it on reload; a later explicit language change saves a new preference. Clear session cancels or invalidates pending work, drops app state, closes previews and ends page reminders. Leaving the travel page also ends its reminder. This cannot erase browser history, HTTP tile caches, downloads, screenshots, OS backups, clipboard contents or external providers' records. There is no stealth or erasure guarantee for those systems.

Location permission is not consent to share location or notify an authority. The app accepts a local suggestion only within 35 km of a supported preset centre and reported accuracy no worse than 5 km; it is a rough city suggestion that the user must confirm. Denied/unavailable/imprecise/out-of-coverage readings return to manual selection. Acquisition has an 8-second timeout; hidden, unmounted, cleared or superseded attempts are invalidated. This is not a measured physical-device accuracy claim. The preset suggestion list has16 cities; the larger public gazetteer is city-search data, not support-service coverage.

The gateway has fixed HTTPS provider hosts, no redirects or arbitrary query language, sanitized errors,25-second server wall timeouts, a12-second cancellable browser wait,1.5MB response limits and bounded five-minute public-response caches (one hour for public city IDs). Cache metadata preserves the original retrieval time. Data and request keys stay in server RAM, without a user identifier. One-process host limits and a120/minute process-wide navigation budget are conservative internal-preview controls, not mass-scale rate limiting. Deterministic emergency/minor routing bypasses the navigation budget. Do not enter private addresses or personal details in a public-data tool.

Global no-referrer, self-only scripts/connect, frame denial and no-store app/API responses remain. Only tile images override the referrer to origin as OSM requires. Permissions Policy allows same-origin geolocation because the founder requested explicit city suggestion; camera and payment remain denied. Same-origin microphone permission supports explicit, user-started local voice-note recording; it is not requested at startup. Merely allowing the capability does not request it. External map scripts, trackers and advertising are not loaded.

## Sharing and reminders

A public TXT travel card contains the selected public city, public destination if chosen, route facts if requested and generic checklist items. It excludes device position and story. A generic check-in WhatsApp URL contains only the displayed neutral message, with no location or trip details. Opening it does not send it: recipient selection and Send happen in WhatsApp. Sakhi cannot observe sending, delivery, availability or an agreed check-in. The existing public resource kit and WhatsApp public-card rules remain.

The separate loved-one update accepts a temporary recipient label and international-format number. It offers fixed neutral messages and an optional separately selected one-time position. Editing a recipient/message/position revokes prior draft approval. A position expires two minutes after acquisition. No contact import, server endpoint or persistent record exists. The preview exposes the exact recipient/message and any position, accuracy and timestamp before transmission. An external open is recorded only as an opening request; sent/replied records are explicitly user-reported and unverified. Delivery always remains unobserved. Clear/revoke cannot unsend or remove another app's records. Native WhatsApp live-sharing assistance explains recipient/duration/Send and Stop sharing, with a last-position visibility warning. Sakhi does not observe or control that native stream.

Hide page is a local cover, stops pending lookups/local location and changes the title to Notes. Quick exit clears local app state and opens Google in the current tab. Neither erases earlier history or prevents device monitoring. The trust page can remove the saved locale preference independently; a later explicit language change saves a new preference.

The local reminder has a page deadline, snooze, cancel and I'm here actions. It is not a server monitor, notification service, automatic contact alert or emergency response. Browser suspension, locking the phone or closing the page can delay or stop it. It must never be relied on for rescue or background protection.

External source/map/message previews show the destination and public fields. Public links carry no story or form data. The emergency tel link uses the device dialler after the user's click. No person, authority or provider receives a referral or complaint through Sakhi. A public correction proposal is temporary local text plus a downloaded file, not a submitted report.

## Offline and operator boundary

The service-worker allowlist caches only versioned public shell, resources, fonts and build assets with SHA-256 integrity checks. No API, query-string URL, story, user draft, travel response or user file enters that cache. OSM tiles are excluded from the service worker and offline export. Map/route/weather services need the network; offline emergency and public support fallback do not depend on them. Hashes do not establish an independent signing root.

Operators must preserve no-access-log settings, disable request telemetry/debug dumps, use HTTPS and protect deployment access. Reverse proxies, hosting logs, browser extensions and compromised devices can undermine these properties. Public deployment still requires independent privacy/security and safeguarding review, source/contact approvals, real-device checks and named operations owners. No legal compliance certification is claimed.

## Local media preview, October 21 revision

Private media acquisition requires an explicit 18-or-older selection. Unspecified age and under18 retain text, symbols and public child pathways. Each selection replaces the preceding preview. Audio is limited to10 MiB/two minutes, existing video to20 MiB/one minute. Voice recording ends at two minutes or the10 MiB bound. No camera capture, automatic transcription, video interpretation, remote ASR, upload or media-sharing endpoint exists. Unsupported formats and denied microphone access have text/symbol/file alternatives. A microphone decision arriving after cancellation stops its tracks and cannot restore a recording.

Media Blob URLs, recorded chunks and streams are temporary. Cover, background, page exit, route unmount, replacement, deletion and five-minute expiry stop acquisition and revoke app-held previews. Clearing app memory cannot delete the source file or OS/browser copies. Preview playback is user controlled; video initially stays muted. Filenames are neither rendered into guidance nor transmitted. Native browser decoders process the local file for playback. Physical codec, screen-reader and device-suspension acceptance remains pending.
