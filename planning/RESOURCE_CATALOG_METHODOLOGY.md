# Recovered resource catalog methodology

Original file not supplied. This replacement was derived from the master specification on 2026-10-19.

The 211 rows are discovery leads. Preserve every original field, including historical state names and HTTP URLs. Canonicalization removes fragments and redundant terminal slashes but does not merge query-dependent functions. Exact URL duplicates are reported; functional duplicates need human review. Ingestion never approves a resource.

Classifications: official_public_portal, public_directory, downloadable_public_data, public_document, open_source_repo, optional_approved_api, partner_only, unverified. Free public reading, official service costs, open-source licensing and API permission are independent fields. Unknown reuse rights stay unknown.

Only the separate public resource pack is visible to users. Its seven entries were checked against official public pages or authoritative official references by the coding agent. Human contact, language and safeguarding signoff remain pending. Preview curation is not production approval or proof of live availability.

Source receipts contain publisher, exact URL, check date, TTL, jurisdiction, eligibility, access class and limits. Review by November 18, 2026; stale specialized records leave default retrieval. The emergency source remains visible with its check date. Phone connection cannot be tested by automated regression tests.

Weekly validation is an explicit maintainer command, not a scheduled automation. The allowlist checker respects robots, makes at most one sequential request per second, does not follow redirects or access login, and writes a report. Content and link changes require a reviewed pull request. A changed page hash is a review lead, not approval. No narrative-driven web browsing exists.
